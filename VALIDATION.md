# Проверка выполнения

## Исследовательский запуск, версия 0.4.0

Пройдены 29 основных тестов. Выполнены 48 попыток: четыре загрузчика,
четыре локальные страницы и три повторения. После изоляции каждой попытки
в отдельном процессе ошибок загрузчиков нет. Получены 42 непустых текста.
Шесть пустых результатов относятся к динамическим страницам при загрузке
через curl_cffi. Пустые результаты сохранены и учитываются в качестве извлечения.

Первый прогон в общем процессе выявил конфликт SDK: после Clearcote вызов
Patchright выдаёт ошибку запуска синхронного API внутри цикла asyncio.
Проверка с отдельным процессом для каждой попытки устранила влияние порядка.
Время загрузчика и полное время изолированного процесса сохраняются раздельно.

Повторное извлечение из 48 сохранённых снимков без сети дало те же тексты и F1.
Тест с изменённым снимком подтвердил отклонение несовпадающего SHA-256.
Корпус синтетический; качество на внешних сайтах и расход памяти браузеров
не оценивались.

Дата проверки — 17.10.2026. Среда — Windows x64, отдельное виртуальное окружение Python.

## Загрузчики, версия 0.1.0

| Проверка | Результат |
|---|---|
| Установка всех дополнительных зависимостей | Пройдена |
| `pip check` | Конфликтов зависимостей нет |
| Основные автоматические тесты | 18 пройдено |
| Сбор с `https://example.com` через curl_cffi | Успешно, HTTP 200, файлы XLSX сохранены |
| Выполнение JavaScript через Patchright | Пройдено |
| Выполнение JavaScript через Clearcote | Пройдено |
| Выполнение JavaScript через Camoufox | Пройдено после исправления манифеста Windows-сборки |
| Чтение сжатого файла по пути с кириллицей в Windows | Пройдено через адаптер файлового дескриптора |

Основные проверки используют локальный HTTP-сервер. Сценарии охватывают извлечение
русского текста, HTTP 403, повтор после HTTP 503, точные дубликаты, отсутствие
загрузчика, пустую выборку, некорректные настройки, коды завершения команды,
сохранность длинных полей и текстовых значений в XLSX.

Браузерная проверка получает страницу с JavaScript, ожидает динамический элемент
и проверяет его присутствие в DOM. Обнаруженное отличие SDK Clearcote от примера
документации учтено в коде: поддержаны объекты Browser и BrowserContext.

Для Camoufox `156.0.1-beta.36` воспроизведена ошибка запуска Windows с кодом
14001. Журнал SideBySide сообщил об отсутствующей зависимой сборке `mozglue`.
Применена команда `tools/repair_camoufox_windows.py --apply`, сохранена исходная
копия исполняемого файла. Описание исходной ошибки опубликовано в
[репозитории разработчика](https://github.com/daijro/camoufox/issues/650).
Отдельно исправлено чтение `fpgen` через путь с кириллицей. Проверены версии
`fpgen` 1.3.0 и `indexed-zstd` 1.7.2.

При установке загружены Chromium `156.0.8078.4` для Patchright, Camoufox
`156.0.1-beta.36` и Clearcote Chromium `150.0.7871.114`.
Полный локальный набор включает 18 основных и 4 браузерных проверки.
GitHub Actions проверяет основные сценарии на Ubuntu с Python 3.11.

Прохождение защит сайтов, скорость массового сбора и фактическая достоверность
внешних материалов не проверялись. Данные локального тестового сайта служат
проверке программы и не являются эмпирическими результатами исследования.

## Объединение с fintech-triage, версия 0.2.0

Проверены 24 основных теста проекта с установленным дополнительным набором
`analysis`. Браузерные проверки в таком запуске исключены, поскольку код
загрузчиков не менялся. В исходном `fintech-triage` прошли 32 теста.
`pip check` не обнаружил конфликтов зависимостей.

Отдельно выполнена команда `tools/demo_semantic.py`. Получены две страницы
локального HTTP-сервера, два уникальных документа и два прогноза. Созданы
`raw.xlsx`, `processed.xlsx`, `analysis.xlsx`, файл модели, синтетический
обучающий XLSX и журналы. По заданному демонстрационному порогу оба прогноза
направлены на проверку оператором. Числа характеризуют исполнение программы,
качество классификации по ним не оценивалось.

Новые тесты проверяют связь URL с прогнозом, повторный текст после очистки,
разбиение на фрагменты, контроль SHA-256 модели до сетевых запросов,
относительные пути модели, сохранение данных при ошибке классификатора и
связь имитированного резюме с фрагментом. Вызовы реального Qwen и загрузка
весов e5 в проверку объединения не входили.

## Локальная модель и обучение, версия 0.3.0

Qwen API удалён из подключаемого пакета. Проверены реальные веса
`cointegrated/rubert-tiny2` на CPU: обучение классификаторов, обработка
длинного входа и извлечение резюме. Полный набор `fintech-triage` завершился
успешно, 37 тестов. В проекте парсинга пройдены 26 основных тестов с
подключённым анализом. Конфликтов зависимостей не обнаружено.

Выполнен сквозной пример с параметрами `--backend rubert --with-summary`.
Обучение выполнено на синтетических строках. Получены тексты двух страниц,
созданы прогнозы и локальные резюме, сохранены XLSX и журналы. Качество на
реальных данных по такому примеру не оценивалось. Резюме извлекает исходные
предложения и не заполняет произвольные поля.
