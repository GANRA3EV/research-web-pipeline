# Сбор веб-данных для исследований

Воспроизводимый пайплайн на Python с загрузчиками **curl_cffi**, **Patchright**,
**Camoufox** и **Clearcote Browser**. Результат работы — исходные страницы и
извлечённые тексты в XLSX, сведения о происхождении данных, диагностика и журналы.

## Последовательность работы

1. Проверка конфигурации и CSS-селекторов до сетевых запросов.
2. Загрузка каждой страницы каждым выбранным инструментом.
3. Сохранение исходного содержимого, HTTP-статуса, времени UTC и SHA-256.
4. Извлечение заголовка и текста; учёт пустых выборок.
5. Поиск точных дубликатов по SHA-256 извлечённого текста.
6. Сохранение диагностики, подсчёта слов и частотности лексики.

Список `engines` задаёт независимые способы получения страницы. Если перечислены
четыре загрузчика, выполняются четыре отдельных запроса. Автоматического перехода
на другой браузер после блокировки нет. Повторные попытки ограничены временными
сетевыми сбоями и HTTP 500, 502, 503, 504. Ответы 403 и 429 фиксируются без повторов.

## Быстрый запуск

Нужен Python 3.11 или новее. Команды выполняются из папки проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe run_all.py --config config/example.json
```

В Linux и macOS путь к Python окружения — `.venv/bin/python`.
Пример обращается к реальному `https://example.com`. Исследовательских данных
в репозитории нет; тестовый корпус создаётся локальным HTTP-сервером.

## Установка браузеров

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[browsers,dev]"
.\.venv\Scripts\python.exe -m patchright install chromium
.\.venv\Scripts\python.exe -m camoufox fetch
.\.venv\Scripts\python.exe run_all.py --config config/all-engines.json
```

Clearcote загружает свой дистрибутив при первом запуске согласно поведению SDK.
Размер загрузок и доступность сборок зависят от разработчиков. На Linux могут
понадобиться системные библиотеки: `python -m patchright install --with-deps chromium`
и `python -m playwright install-deps firefox`.

В Windows зависимость `indexed_zstd` версии 1.7.2 может не читать файлы из пути
с кириллицей. Для Camoufox добавлен временный адаптер чтения через файловый
дескриптор. Файлы установленных пакетов не изменяются. Версии `fpgen` и
`indexed-zstd` закреплены; адаптер проверяется отдельным тестом.

Некоторые официальные Windows-сборки Camoufox не запускаются из-за записи
`mozglue` в манифесте приложения. Ошибка описана в
[обсуждении разработчиков № 650](https://github.com/daijro/camoufox/issues/650)
и воспроизведена при проверке сборки `156.0.1-beta.36`. Для такого случая
в проект включено отдельное исправление с предварительным просмотром.

```powershell
.\.venv\Scripts\python.exe tools/repair_camoufox_windows.py
.\.venv\Scripts\python.exe tools/repair_camoufox_windows.py --apply
```

Команда с `--apply` изменяет только блок зависимости `mozglue` в установленном
`camoufox.exe`. Размер файла сохраняется. Рядом создаются исходная копия
`camoufox.exe.original` и отчёт `camoufox.exe.repair.json` с SHA-256 до и после
изменения. Для отката при закрытом браузере скопируйте исходную копию поверх
`camoufox.exe`. После обновления браузера исправление может понадобиться снова.
При отсутствии указанной зависимости команда оставляет файл без изменений.
Обычный запуск пайплайна исполняемый файл не изменяет.

| Загрузчик | Выполнение JavaScript | Назначение |
|---|---|---|
| curl_cffi | Нет | HTTP-запросы и получение исходного HTML |
| Patchright | Да | Автоматизация Chromium |
| Camoufox | Да | Автоматизация Firefox |
| Clearcote | Да | Автоматизация модифицированного Chromium |

## Настройка источников

Скопируйте `config/example.json` и замените `sources` своими адресами.

```json
{
  "engines": ["patchright"],
  "headless": true,
  "timeout_seconds": 30,
  "delay_seconds": 1,
  "retries": 1,
  "retry_delay_seconds": 2,
  "sources": [{
    "id": "example",
    "url": "https://example.com",
    "title_selector": "h1",
    "text_selector": "body",
    "wait_for_selector": "h1"
  }]
}
```

`title_selector` выбирает первый заголовок; `text_selector` собирает текст всех
совпавших элементов. Вложенные совпадения могут повторять текст, поэтому лучше
выбирать непересекающиеся элементы. Скрипты, стили и шаблоны удаляются перед
извлечением. `wait_for_selector` применяется только в браузерных загрузчиках.
Для динамических сайтов задайте селектор элемента, который появляется после
получения нужных данных. Фиксированных пауз для ожидания JavaScript нет.

Не помещайте секреты в URL или конфигурацию: адреса сохраняются в реестре.
TLS-проверка остаётся включённой. Интерактивный вход и обработка CAPTCHA
в текущую версию не входят.

## Сохраняемые файлы

```text
runs/<время_UTC>/
  data/
    raw.xlsx                  # HTML или DOM, адреса, статусы и контрольные суммы
    processed.xlsx            # заголовки, тексты, число слов и связи дубликатов
  logs/
    manifest.json             # параметры, версии пакетов, Git-коммит, хэши файлов
    attempts.json             # результат каждой попытки и класс ошибки
    diagnostics.json          # пропуски, дубликаты, объём и ограничения
    word_count_report.json    # число слов по записям и уникальному корпусу
    word_frequency_report.json
```

Книги обновляются после каждой попытки через временный файл. Повторное использование
папки запуска отклоняется. Путь можно задать через `--output runs/my-run`.
После завершения программа перечисляет созданные файлы. Код возврата 0 означает,
что все пары «источник, загрузчик» дали непустой текст; 1 означает частичные или
полные ошибки сбора; 2 означает ошибку параметров или файлов.

Длинные поля сохраняются частями на листе `long_values` с номером строки,
названием поля и порядком частей. Ограничение размера ячейки Excel не приводит
к усечению текста. Строки, начинающиеся со знака `=`, сохраняются как текст.
Недопустимые XML-символы записываются как печатные последовательности `\uXXXX`.
Исходный SHA-256 вычисляется до такого преобразования.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q -m "not browser"
$env:TEST_BROWSERS = "1"
.\.venv\Scripts\python.exe -m pytest -q -m browser
```

Основные тесты используют локальный сервер и проверяют HTTP-загрузку, русский
текст, повторные попытки, дубликаты, пустые выборки, ошибки конфигурации и XLSX.
Браузерные тесты проверяют выполнение JavaScript всеми тремя браузерами.
Они требуют предварительной установки дистрибутивов. GitHub Actions запускает
основные проверки при отправке изменений. Браузерные проверки доступны вручную
через `workflow_dispatch` с параметром `browsers`.

## Границы применимости

Загрузчик curl_cffi сохраняет полученный HTML; браузеры сохраняют DOM после
навигации и ожидания селектора. Разница между результатами может отражать
выполнение JavaScript, время запроса или персонализацию страницы.
Программа не проверяет фактическую достоверность собранных утверждений и
не подтверждает библиографические записи. Включение материалов в научную
статью требует отдельной библиографической и содержательной проверки.

Число слов определяется разбиением по пробельным символам. Частотный отчёт
учитывает словоформы без лемматизации; удаление стоп-слов не выполняется.
Дубликаты сохраняются для аудита и помечаются полем `duplicate_of`.
Общий объём считается только для уникальных непустых текстов.
Пустой текст исключается из уникального корпуса.

Содержимое сайтов и доступность браузерных сборок меняются. Пакеты верхнего
уровня закреплены в `pyproject.toml`; все установленные версии фиксируются
в журнале запуска. Побитовая воспроизводимость внешних страниц не обещается.
Сборка браузера может меняться независимо от версии SDK.
Браузерные запросы выполняются в отдельных сессиях. Cookies между страницами
не переносятся; запуск браузера для каждого адреса увеличивает время сбора.
Скорость, обнаружение автоматизации и прохождение защит не измерялись.
Camoufox публикует предупреждение о стадии разработки; условия распространения
Clearcote и доступ к сборкам нужно сверять с документацией разработчика.
