# Совместное выполнение парсинга и классификации

В `research-web-pipeline` подключён пакет из
[GANRA3EV/fintech-triage](https://github.com/GANRA3EV/fintech-triage).
Зависимость закреплена на коммите `567cb7f4806869d4676af3ba50f9acf3da27b6a3`.
Классификатор и очистка текста импортируются из исходного пакета. Копий
реализации обучения в проекте парсинга нет.

## Назначение

Последовательность выполнения — URL, HTML или DOM, извлечённый текст, очистка,
точные дубликаты, фрагменты, классификатор, XLSX с прогнозами и источниками.
Используется `TicketModel` с TF-IDF, rubert-tiny2 или multilingual-e5. Результаты содержат
основную и дополнительную темы, срочность, оценки уверенности и причины проверки
оператором. Локальное извлечение резюме подключается отдельным параметром.

Классификатор обучается с учителем. Для запуска нужен заранее подготовленный
`model.joblib` из `fintech-triage`. Само получение веб-страниц не создаёт
разметку и не обучает предметные категории. Финтех-модель не предназначена
для автоматического тематического анализа произвольной научной литературы.

## Установка

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[analysis,dev]"
```

Для модели с признаками multilingual-e5 добавьте зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[analysis,embeddings]"
```

Браузерные загрузчики устанавливаются через дополнительный набор `browsers`,
как описано в основном README. Установка библиотек не загружает веса e5;
первая попытка прогноза может потребовать загрузки модели.

## Полный пример без внешних сайтов

```powershell
.\.venv\Scripts\python.exe tools/demo_semantic.py --output runs/semantic-demo
```

Команда создаёт синтетический обучающий XLSX, обучает TF-IDF-классификатор
двух демонстрационных категорий, сохраняет модель и её SHA-256, запускает
локальный HTTP-сервер и вызывает обычный `run_all.py`. Сервер закрывается
после завершения. Сохранённые адреса локального сервера относятся только к
такому запуску. Для повторения примера выберите новую папку `--output`.

Демонстрационные тексты придуманы для проверки программного взаимодействия
и помечены как синтетические. По ним нельзя оценивать качество работы
на реальных обращениях или веб-страницах. Порог 1.01 в примере направляет
все прогнозы на проверку оператором; подбор порога на синтетических строках
не выполняется.

## Использование обученной модели

Обучите модель по инструкции `fintech-triage`, затем добавьте в конфигурацию
парсинга раздел `analysis`. Пример файла `config/semantic.template.json`
нужно заполнить адресами страниц, путём к своей модели и её контрольной суммой.

```powershell
Get-FileHash -Algorithm SHA256 artifacts/model.joblib
.\.venv\Scripts\python.exe run_all.py --config config/semantic.template.json
```

Путь `model_path` считается относительно папки конфигурационного файла.
SHA-256 проверяется до запросов к страницам. `joblib` способен исполнять код
при чтении: используйте только доверенную модель. Совпадение контрольной
суммы подтверждает соответствие выбранному файлу, а не безопасность его кода.

`chunk_words` задаёт число слов во фрагменте. Прогнозы сохраняются отдельно
для каждого фрагмента. Объединение тем в одну метку документа не выполняется.
Разбиение по словам не гарантирует соблюдения предела токенов e5. Для корпуса
с длинными словами или разметкой нужна отдельная проверка токенизации.

`with_summary` по умолчанию отключён. При значении `true` локальная модель
`cointegrated/rubert-tiny2` выбирает исходные предложения для резюме.
Qwen API удалён. Первая загрузка весов требует сети; тексты обрабатываются
на CPU. Старый параметр `with_llm` поддерживается как совместимое имя.
Извлечение произвольных полей не выполняется; `fields` остаётся пустым.

Установка и запуск нового варианта:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[analysis,local-hf]"
.\.venv\Scripts\python.exe tools/demo_semantic.py --backend rubert --with-summary --output runs/rubert-demo
```

Режим `rubert` обучает классификаторы на признаках компактного кодировщика.
В демонстрации используются синтетические обучающие строки. Для оценки качества
нужен отдельный размеченный корпус. Веса самого кодировщика заморожены.
Обучение с временным разбиением и сохранением метрик доступно командой `train`
исходного проекта `fintech-triage` с параметром `--backend rubert`.

## Выходные файлы и происхождение

Добавляются `data/analysis.xlsx` и `logs/analysis_report.json`. XLSX содержит
четыре листа.

| Лист | Содержание |
|---|---|
| documents | Уникальные очищенные тексты и `analysis_id` |
| provenance | `record_id`, URL, загрузчик, заголовок и связь с `analysis_id` |
| chunks | Фрагменты с `chunk_id`, порядковым номером и `analysis_id` |
| predictions | Темы, срочность, уверенность и признаки проверки по `chunk_id` |

Связь с `raw.xlsx` и `processed.xlsx` сохраняется через `record_id`.
Тексты, совпавшие после очистки без учёта регистра, анализируются один раз.
Все их исходные URL остаются на листе `provenance`. Числовые идентификаторы
клиентов и переписок не выдумываются: адаптер вызывает классификатор напрямую.
Исходная очистка `fintech-triage` может удалить подпись после слов «С уважением»
и заменить контакты. Для статей и документов пригодность такого удаления
нужно проверять отдельно. Полное обезличивание не гарантируется.

Результаты сохраняются после каждого прогноза. При ошибке анализа уже собранные
страницы остаются на диске; журнал содержит класс ошибки без текста исключения.
Код завершения равен 1 при ошибке анализа или отсутствии пригодных текстов.
При неверном файле модели запросы к страницам не начинаются.

Тема и срочность веб-фрагмента зависят от обучающей разметки. Оценки уверенности
не калиброваны. Проверка предметного качества и сравнение TF-IDF с e5 требуют
отдельного размеченного корпуса. Сбор страниц не заменяет проверку источников
для научной публикации.
